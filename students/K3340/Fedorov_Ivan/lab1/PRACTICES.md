# Соответствие практикам 1.1–1.3

Практики оформлены отдельными коммитами ветки `lab1`.

## Практика 1.1 — модель данных и ORM

Коммит: `practice 1.1: add SQLModel domain models and relationships`.

- предметная область: управление личными финансами;
- 8 таблиц SQLModel;
- связи one-to-many: пользователь → счета, категории, транзакции, бюджеты, цели и теги;
- связь many-to-many: транзакции ↔ теги;
- ассоциативная сущность `transaction_tag` с собственными полями `note` и `added_at`;
- PostgreSQL задаётся через `DB_ADMIN`.

## Практика 1.2 — FastAPI и CRUD

Коммит: `practice 1.2: implement typed CRUD API and nested responses`.

- раздельные роутеры предметных областей;
- CRUD для счетов, категорий, транзакций, бюджетов, целей и тегов;
- JWT-аутентификация и проверка владельца объектов;
- вложенные ответы для one-to-many и many-to-many;
- фильтрация транзакций, отчёт по периоду, состояние бюджетов;
- аннотации типов входных и выходных значений;
- интеграционные тесты основных сценариев.

## Практика 1.3 — миграции и запуск

Коммит: `practice 1.3: configure Alembic and PostgreSQL deployment`.

- Alembic настроен на metadata SQLModel;
- начальная и дополнительная миграции с поддержкой upgrade/downgrade;
- запуск PostgreSQL и API через Docker Compose;
- локальный запуск, тестирование и команды проверки описаны в README.

## Итоговые задания

- Реализованы CRUD-операции и вложенные модели.
- Реализованы обе требуемые разновидности связей.
- Ассоциативная таблица имеет дополнительные атрибуты и отдельные API-операции.
- Бизнес-правила проверяют принадлежность объектов пользователю, совместимость типа категории и транзакции, корректность периода бюджета и положительные суммы.
- Баланс счёта автоматически пересчитывается при создании, изменении и удалении транзакции.
